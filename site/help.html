方案 A：網站與日更放 GitHub Pages

  1. 建立自己的 GitHub public repository，預設分支使用 main。
  2. 解壓「完整專案」ZIP，把其內容上傳至 repository 根目錄。必須包含 .github/、site/、content/、scripts/、tests/，不要只上傳 ZIP 檔。
  3. 到 Settings → Pages → Source，選 GitHub Actions。
  4. 到 Actions → 每日九點更新與發布 → Run workflow，先執行一次。
  5. 打開部署步驟回傳的網站網址。到「今日閱讀」查看消息更新狀態，確認不是 offline，然後分享網址給朋友。

這個方案不用更改 config.js 的 feedUrl。工作流程會每天產生網站與最新公開 JSON。

方案 B：網站放 InfinityFree

  1. 解壓「InfinityFree上傳包」，將檔案與子資料夾放進 htdocs/。確認 htdocs/index.html 存在。
  2. 開啟你的網站，九科、已提交的原創導讀及每日練習即可使用。
  3. 官方消息日更另依方案 A 啟用 GitHub Pages，取得實際部署網址，再加上 /updates/daily.json。用瀏覽器確認能開啟資料。
  4. 在下方產生 config.js，下載後上傳覆蓋 InfinityFree 的同名檔案。
  5. 回到網站，點「今日閱讀 → 更新消息」，查看成功時間與來源狀態。
InfinityFree 免費方案停用 cron 並禁止定時背景請求。本方案只在外部產生資料，不對 InfinityFree 定時呼叫；正常訪客開啟網頁後，再讀取外部公開資料。

InfinityFree 官方限制說明 ↗

產生公開設定檔

只填網站名稱與公開 JSON 網址。不要輸入 API Key、登入密碼或私人憑證。

GitHub Pages 直接架站可留空；InfinityFree 要啟用日更，請填已成功部署的外部公開資料網址。

更新與分享，哪些會自動發生？

每天九點：Codex 本對話排程啟動新撰、查核及 GitHub 提交；新導讀保存原文日期並可選歷史文章。既有九科練習仍作輪替複習，不宣稱每天新增題目。本機排程須電腦開機及應用程式運作，完成時間依來源、查核與發布而異。

排程執行：新聞來源在外部抓取，可能延遲。若失敗，網站標示失敗或保留先前內容。需要定期檢查 GitHub Actions，長時間沒有 repository 活動時，排程可能停用。

朋友分享：分享公開網址即可。朋友的筆記、作答與進度存在各自瀏覽器，沒有共享或登入同步。不要把含個人資料的備份上傳到公開 repository。

官方消息僅提供來源標題、日期與連結，不是完整新聞查證服務；原創導讀會附來源與 AI 查讀紀錄，尚無人工審定；無今日新文時保留前篇日期，不冒充更新。
